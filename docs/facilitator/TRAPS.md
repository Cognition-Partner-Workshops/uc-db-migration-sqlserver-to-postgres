# Facilitator notes: planted migration traps

For the facilitator only. Not linked from the README, AGENTS.md or the lab. Each trap is real T-SQL behaviour that a line-by-line conversion gets wrong, and each has a reconcile control that catches it.

| # | Trap | Where in the legacy estate | What a naive conversion does | Control that catches it | Correct PostgreSQL |
|---|---|---|---|---|---|
| 1 | Case-insensitive collation (`Latin1_General_100_CI_AS`) | Database default; every code lookup | `text` parameters compared with `citext` columns are case-sensitive, so lookups miss; `usp_claim_reserve_set` finds no payments for `'indemnity'` and accepts a reserve below paid | `usp_policyholder_get` "by email, different case"; `usp_policy_create` "lower-case product and broker codes"; `usp_rate_quote` "lower-case codes"; `usp_claim_open` "lower-case policy number"; `usp_claim_reserve_set` "reserve below paid, lower-case type"; `usp_report_broker_production` "top 5 in 'de'" | `citext` columns **and** `citext` parameters |
| 2 | `MONEY` vs `DECIMAL` rounding | `fn_pro_rata`, `usp_premium_schedule_build`, `usp_claim_payment_record` | `numeric` division rounds; MONEY keeps 4 dp by truncation, so instalments and the balancing last instalment differ by 0.0001 | `fn_pro_rata` "money truncation"; `usp_premium_schedule_build` "monthly plan, half-cent premium"; business rule *premium schedule totals* | `trunc(x, 4)` where money is divided |
| 3 | Integer division | `usp_report_loss_ratio`: `ISNULL(paid_cents, 0) * 100 / NULLIF(premium_cents, 0)` and `claim_count * 100 / policy_count` on integers | Casting to numeric "fixes" it and the report shows decimals the legacy report never produced | `usp_report_loss_ratio` "calendar 2025", "H1 2026" | Keep integer division |
| 4 | `DATEDIFF(MONTH, …)` counts boundaries | `fn_months_between`, `usp_report_claims_ageing`, `usp_rate_renewal` (36-month tenure), `usp_batch_lapse_overdue` | `age()` counts elapsed months: 31 Jan → 1 Mar is 2 in T-SQL and 1 with `age()`; claims move age band, a renewal loses its tenure discount | `fn_months_between` "month-end boundaries"; `usp_report_claims_ageing` "as of 1 April 2026 (month-end losses)"; `usp_rate_renewal` "36-month tenure boundary"; **`make reconcile-naive`** | Year*12 + month arithmetic (`$(NS).fn_months_between`) |
| 5 | `ISNULL` vs `COALESCE` typing | `usp_report_claims_ageing`: `UPPER(ISNULL(cause_code, 'UNSPECIFIED'))` where `cause_code` is `VARCHAR(10)`, so it returns `UNSPECIFIE` | `coalesce(cause_code::text, 'UNSPECIFIED')` returns the full literal and a different group key appears | `usp_report_claims_ageing` (also in the naive diff) | `left(coalesce(cause_code, 'UNSPECIFIED'), 10)` |
| 6 | `'' + NULL` vs `CONCAT` | `usp_report_broker_production`: `broker_name + N' <' + email + N'>'`; `fn_format_name` | `concat()` ignores NULL and returns `'Name <>'` where the legacy report returns NULL | `usp_report_broker_production`; `fn_format_name` "NULL, empty and blank middle names" | `\|\|` (NULL-propagating) |
| 7 | `TOP` without `ORDER BY` | `usp_rate_renewal`: `SELECT TOP (1) ... FROM policy_version WHERE policy_id = @policy_id` relies on clustered index `cx_policy_version_latest (policy_id, effective_from DESC, version_no DESC)` | `LIMIT 1` without `ORDER BY` returns heap order and the same-day correction is skipped | `usp_rate_renewal` "same-day correction"; `usp_policy_get` "same-day correction is current" (Phase 1, already handled) | `ORDER BY effective_from DESC, version_no DESC LIMIT 1` |
| 8 | `@@ROWCOUNT` after triggers | Triggers store `@@ROWCOUNT` in `audit_log`; `usp_claim_payment_record`, `usp_claim_close` and `usp_batch_lapse_overdue` read `@@ROWCOUNT` after DML that fires a trigger | A `FOR EACH ROW` trigger logs one audit row per row with `row_count = 1`; `GET DIAGNOSTICS` in the wrong place reports the trigger's count | `trg_policy_status_audit` "multi-row status update"; `trg_claim_status_audit` "reopen two claims, one unchanged"; `trg_claim_payment_audit` "two payments in one statement"; `usp_claim_close` "already closed" | `FOR EACH STATEMENT` triggers with transition tables; `GET DIAGNOSTICS` straight after the DML |

## Demo moment

`make reconcile-naive` deploys `naive_conversion/610_report_claims_ageing.sql` (traps 4 and 5) into `NS=naive`. Expected: 33 PASS, 1 FAIL (`dbo.usp_report_claims_ageing`), 17 NOT CONVERTED. The diff shows claim counts moving between age bands and an `UNSPECIFIED` group key the legacy report never produced.
