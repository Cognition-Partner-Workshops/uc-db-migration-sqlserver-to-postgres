# T-SQL → PL/pgSQL construct map

Every construct listed here is present in `source/sqlserver/` (`make coverage` checks all 38). The **Risk** column covers what reconcile has caught, or would catch, when the conversion is done line by line.

| T-SQL construct | Where in the estate | PostgreSQL 18 / Aurora equivalent | Risk |
|---|---|---|---|
| `IDENTITY(1,1)` | most tables | `GENERATED BY DEFAULT AS IDENTITY` + `setval` after load (`reset_identities()`) | Identity not moved past loaded ids: first insert collides |
| `CREATE SEQUENCE` / `NEXT VALUE FOR` in `DEFAULT` | `policy.policy_number`, `claim.claim_number` | `CREATE SEQUENCE` + `DEFAULT 'P' \|\| lpad(nextval(...)::text, 9, '0')` | Sequence not advanced after load |
| `ROWVERSION` | `claim.row_ver` | dropped; `xmin` for optimistic concurrency | Callers comparing binary versions need an API change |
| Computed column | `policyholder.full_name` | `GENERATED ALWAYS AS (...) STORED` | Expression must be immutable: no `concat()` on non-text |
| `MONEY` | premiums, payments, reserves | `numeric(19,4)` | MONEY division truncates at 4 dp; `numeric` rounds |
| `UNIQUEIDENTIFIER` / `NEWID()` | `external_ref`, `correlation_id` | `uuid` / `gen_random_uuid()` (`pgcrypto`, core since PG13) | Upper-case string comparisons in clients |
| `DATETIMEOFFSET` | `paid_at`, `opened_at` | `timestamptz` (stored as UTC; offset not kept) | Original offset lost; report in UTC or keep a separate offset column |
| `DATETIME2(3)` / `SYSUTCDATETIME()` | audit columns | `timestamp(3)` / `now() AT TIME ZONE 'UTC'` | `now()` is transaction start time |
| `BIT` | `is_active` | `boolean` | Clients sending 0/1 |
| `NVARCHAR` + `Latin1_General_100_CI_AS` | all codes, names, e-mails | `citext` for case-insensitive columns **and parameters**; `text` elsewhere | `citext = text` compares case-sensitively; trailing spaces are significant in PG |
| Filtered index `WHERE ...` | `policyholder.email`, open claims | partial index | — |
| `INCLUDE` columns | `ix_policy_broker` | `INCLUDE` (PG11+) | — |
| Clustered index | `cx_policy_version_latest` | B-tree index; PG has no clustered storage order | Any query relying on physical order |
| `TOP (n)` | renewals, reports | `LIMIT n` | `TOP` without `ORDER BY` relies on clustered order |
| `TOP (n) ... ORDER BY` with `@n` | broker production | `LIMIT p_n` | — |
| `OFFSET ... FETCH` | — (PG uses same syntax) | `OFFSET ... FETCH` | — |
| `ISNULL(a, b)` | reports, batch | `coalesce(a, b)` | `ISNULL` returns the type of `a` (truncation); `COALESCE` uses the widest type |
| `IIF` | rating, batch | `CASE WHEN` | — |
| `+` string concatenation | `fn_format_name`, broker contact | `\|\|` | `concat()` ignores NULL; `+` and `\|\|` propagate NULL |
| `CONCAT` / `CONCAT_WS` | names | `concat` / `concat_ws` | — |
| `STRING_AGG ... WITHIN GROUP (ORDER BY)` | TVF | `string_agg(x, ',' ORDER BY ...)` | — |
| `DATEDIFF(MONTH/YEAR/DAY, a, b)` | ageing, renewal, rating, batch | boundary arithmetic (`$(NS).fn_months_between`), `b - a` for days | `age()` counts elapsed time, not boundaries |
| `DATEADD`, `EOMONTH`, `DATEFROMPARTS` | schedules | `+ interval`, `date_trunc('month', d) + interval '1 month - 1 day'`, `make_date` | `DATEADD(MONTH)` and `+ interval '1 month'` both clamp to month end; chained adds differ |
| `int / int` | loss ratio | `/` on integers (truncates in both) | "Fixing" it to numeric changes results |
| Scalar UDF | `fn_*` | `LANGUAGE sql IMMUTABLE` function | Volatility marking affects plans and generated columns |
| Inline TVF | `tvf_policy_coverage_summary` | `RETURNS TABLE ... LANGUAGE sql` | — |
| `CROSS APPLY` / `OUTER APPLY` | views, ageing | `CROSS JOIN LATERAL` / `LEFT JOIN LATERAL ... ON true` | — |
| `PIVOT` | `vw_policy_coverage_pivot` | `sum(...) FILTER (WHERE ...)` (or `tablefunc.crosstab`) | Pivot column list is static |
| CTE / recursive CTE | reports, schedule build | `WITH` / `WITH RECURSIVE` | — |
| `ROW_NUMBER() OVER` | latest version | same; or `DISTINCT ON` | Ties: add a deterministic tiebreaker |
| `MERGE` | `usp_claim_reserve_set`, broker commission | `MERGE` (PG15+) or `INSERT ... ON CONFLICT` | `MERGE ... OUTPUT $action` → PG17 `RETURNING merge_action()`; keep PG15-compatible logic for Aurora version spread |
| `OUTPUT inserted.*` | creates, reserve set | `RETURNING` | — |
| Temp tables `#t` | loss ratio, batch | `CREATE TEMP TABLE ... ON COMMIT DROP` or CTEs | Temp tables in PL/pgSQL survive the call unless dropped |
| Table variables `@t` | schedule build, batch | CTE, array, or temp table | — |
| Cursor (`DECLARE CURSOR`, `FETCH NEXT`, `@@FETCH_STATUS`) | lapse batch | `FOR rec IN SELECT ... LOOP` | — |
| `WHILE` | schedule build | `FOR i IN 1..n LOOP` / `WHILE` | — |
| Dynamic SQL `sp_executesql` | broker production | `RETURN QUERY EXECUTE format(... %I ...) USING ...` | Injection: use `format('%I')` and `USING`, never concatenation |
| `TRY/CATCH`, `THROW 5xxxx`, `RAISERROR` | all write procedures | `BEGIN ... EXCEPTION WHEN ... END`, `RAISE EXCEPTION '...' USING ERRCODE = 'P0001'` | Message text must match; SQL Server error number goes into `DETAIL` or `HINT` |
| `BEGIN TRAN / COMMIT / ROLLBACK`, `XACT_ABORT` | write procedures | function runs in caller's transaction; procedures can `COMMIT` | Partial work on error is rolled back by the caller, not by the routine |
| `@@ROWCOUNT` | triggers, claims, batch | `GET DIAGNOSTICS v = ROW_COUNT` straight after the statement | Must be read before any other statement |
| `SCOPE_IDENTITY()` | creates | `RETURNING id INTO v` | — |
| Triggers with `inserted` / `deleted` | 3 audit triggers | `AFTER ... FOR EACH STATEMENT` + `REFERENCING NEW TABLE AS inserted OLD TABLE AS deleted` | `FOR EACH ROW` changes counts; multi-row updates |
| `UPDATE()` in triggers | status audits | compare `old.status IS DISTINCT FROM new.status` via transition tables | — |
| `FOR JSON PATH`, `WITHOUT_ARRAY_WRAPPER` | `usp_report_policy_json` | `json_build_object`, `json_agg` | NULL keys omitted by FOR JSON; `json_strip_nulls` |
| `SET NOCOUNT ON` | all procedures | drop | — |
| `GO` batches, `CREATE OR ALTER` | all files | `CREATE OR REPLACE FUNCTION`; one file per object | `CREATE OR REPLACE` cannot change the return type: drop first |
| Procedure result sets | readers, reports | `RETURNS TABLE` / `RETURNS SETOF` functions | Clients move from `EXEC` to `SELECT * FROM fn(...)` |

Babelfish for Aurora PostgreSQL would run much of this T-SQL unchanged over the TDS protocol. This lab deliberately does not use it: the target is native PostgreSQL so the estate leaves T-SQL behind.
